## ai-31: Imperceptible Statistical Token Watermarking

| | |
|:---|:---|
| **Problem** | Platforms must verify whether text was generated by a specific LLM to satisfy compliance mandates (such as EU AI Act Article 50) and prevent synthetic misinformation. However, inserting visible markers destroys user experience, rule-based heuristics are trivial to evade, and post-hoc statistical classifiers suffer from high false-positive rates on natural human writing. |
| **Root cause** | Traditional LLM generation produces output tokens based purely on learned vocabulary probability distributions. Once detached from the runtime server, raw text contains no inherent signature connecting it to the generating model or organization. |
| **Key Concept** | Shift the autoregressive sampling probability distribution at inference time using a pseudo-random seed keyed on a sliding context window and a private watermarking key, subtly biasing token selection toward candidates with elevated watermark scores ($g$-values). |

> **Strategy**:
> 1. **Context Window Seeding**: At step $t$, compute a deterministic pseudo-random seed $S_t = \text{Hash}(K_{\text{secret}} \mathbin{\Vert} w_{t-h}, \dots, w_{t-1})$ using a private key and a sliding window of the previous $h$ generated tokens.
> 2. **G-Value Generation**: Generate uniform pseudo-random watermark scores $g(w) \in [0, 1)$ for every token candidate $w$ in the vocabulary from seed $S_t$.
> 3. **Biased Sampling**: Modulate the logit distribution to subtly favor tokens with higher $g$-values during top-$p$ / top-$k$ or temperature sampling, preserving the overall semantic probability distribution without degrading perceptual output quality.
> 4. **Model-Free Statistical Detection**: A verification detector tokenize the candidate text, recomputes the expected $g$-values for each token using $K_{\text{secret}}$, and computes the empirical mean $\bar{g}$. For unwatermarked text, $\bar{g} \approx 0.50$; for watermarked text, $\bar{g}$ is statistically elevated ($> 0.50$), establishing verification confidence as a function of sequence length without requiring the underlying LLM weights.
>
> **Tradeoff**: Maintains full text readability and enables low-latency verification without running billion-parameter models. However, statistical confidence scales with token count: very short texts (<100 tokens) yield weak statistical signals, and aggressive token disruption (e.g. synonym replacement or heavy editing) gradually erodes the watermark signal.
>

## ai-32: Cryptographic Content Provenance (C2PA)

| | |
|:---|:---|
| **Problem** | AI-generated images, audio, video, and documents are easily repurposed, edited, or re-encoded across platforms, erasing original creation context and exposing organizations to copyright, compliance, and deepfake verification liabilities. |
| **Root cause** | Digital asset containers (JPEG, PNG, MP4, WebM) separate payload data from standard EXIF metadata, which is typically unauthenticated, easily spoofed, or silently discarded by intermediate transformation tools and CDNs. |
| **Key Concept** | Embed cryptographically signed provenance manifests (C2PA Content Credentials) directly into standardized binary metadata segments (e.g., JPEG APP11 / JUMBF boxes) containing verifiable claims about model identity, generation parameters, parent assets, and editing history. |

> **Strategy**:
> 1. **Manifest Assembly**: Construct a C2PA manifest containing structured JSON-LD assertions: asset creator identity, AI model identifier, generation timestamp, and processing ingredients.
> 2. **Cryptographic Signing**: Sign the manifest hash using an authenticated X.509 private certificate issued by an approved trust list authority (C2PA Trust Anchor).
> 3. **Format-Standard Embedding**: Embed the signed manifest into standard container chunks (e.g., JPEG APP11 markers, PNG `eXIf`/`caPA` chunks, or MP4 `moov` atoms) ensuring backwards compatibility with media decoders.
> 4. **Decentralized Verification**: Client applications and inspection portals (e.g. C2PA viewers) validate certificate chains and verify cryptographic hashes locally without depending on centralized lookup APIs.
>
> **Tradeoff**: Provides verifiable, tamper-evident non-repudiation and fine-grained audit trails across cooperating ecosystem tools. However, metadata segments can be intentionally stripped by sanitization tools (`watermarks-remover`, ExifTool) or re-encoding services that drop unknown application markers.
>
> **Cross-reference**: [Content Credentials (C2PA)](../../reference-dictionary/ai-ml-llm.md#content-credentials-c2pa) — Glossary definition. [HSM & Cryptography](../../reference-dictionary/hsm-cryptography.md) — Key signing and certificate validation.

## ai-33: Dual-Layer Synthetic Content Governance

| | |
|:---|:---|
| **Problem** | Relying on a single mechanism for AI content attribution creates single points of failure: metadata-only approaches (C2PA) are stripped when files are converted or scrubbed, whereas in-band statistical watermarks (SynthID) decay when text is paraphrased or back-translated. |
| **Root cause** | In-band and out-of-band protections operate on different physical layers: metadata is external to the perceptual payload and easily separated, whereas statistical watermarks are embedded within the token/pixel payload and susceptible to semantic restructuring. |
| **Key Concept** | Deploy a defense-in-depth architecture combining in-band generative watermarking (for survivable signal preservation across format conversions) with out-of-band cryptographic provenance (for tamper-evident auditability and compliance). |

> **Strategy**:
> 1. **In-Band Generative Injection**: Apply statistical token biasing (text) or imperceptible spectral frequency modulation (images/audio) during the core inference forward pass.
> 2. **Out-of-Band Manifest Attestation**: Attach signed C2PA credentials to the output container specifying the generating system, timestamp, and active watermarking algorithm version.
> 3. **Hierarchical Verification Pipeline**:
>    - *Primary Check*: Validate C2PA cryptographic signature for immediate, high-fidelity attribution.
>    - *Fallback Check*: If C2PA metadata is missing or invalid (due to re-encoding or stripping), execute statistical watermark scoring over the raw tokens or pixel matrices.
> 4. **Asymmetric Trust Policy**: Treat a positive watermark or valid C2PA manifest as definitive confirmation of AI generation; treat negative results with calibrated skepticism since adversarial paraphrasers or segment strippers can weaken signals below detection thresholds.
>
> **Tradeoff**: Maximizes end-to-end attribution resilience across both accidental media conversions and intentional sanitization attempts. Adds slight computational overhead to inference sampling and requires maintaining secure key-management infrastructure for both cryptographic signing keys and statistical watermarking seeds.
>
> **Cross-reference**: [AI-Aware Observability](36-ai-key-takeaways.md#ai-20) — Metrics for detection confidence. [Zero Trust Architecture](../../reference-dictionary/security-iam.md#zero-trust) — Defense-in-depth principles.

| Strategy | Layer | Survivability | Vulnerability / Evasion | Primary Use Case |
|:---|:---|:---|:---|:---|
